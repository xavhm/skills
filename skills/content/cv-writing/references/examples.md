# Positioning and rewrite patterns

Adapted from the eight profile examples and eight bullet rewrites in the user's supplied article. Read when choosing the opening or improving generic bullets. Bracketed values are drafting slots, never facts to add to a real CV. Replace them only with verified candidate evidence; omit an unsupported clause. No bracketed slot may remain in a submission-ready resume.

## Eight summary approaches

Select the approach matching both the candidate and target. These templates show content order; tighten the populated text to the skill's sentence and rendered-line limits.

### 1. Entry-level or new graduate

**Use when:** Professional experience is limited, often under two years, and education or projects supply the strongest proof.

> [Qualification] graduate with hands-on experience building [application type] using [core stack]. Built [verified project scope] including [specific application and supported result]. Applied [relevant engineering capabilities] through [actual project context].

**Select evidence:** Deployed projects, coursework with substantial implementation, real users if known, or measured technical performance. Identify academic/personal work accurately. A production claim needs an actual production context.

### 2. Mid-level, performance focus

**Use when:** The candidate has credible product delivery and measured improvements, often around three to five relevant years.

> Full-Stack Developer with [relevant years] building [products] using [core stack]. Reduced [specific measure] from [baseline] to [result] through [actual intervention]. Delivered [end-to-end feature or scope] for [verified audience or scale].

**Select evidence:** Loading time, API latency, user-facing improvements, and breadth of contribution. Distinguish user counts from requests and production measurements from tests.

### 3. Mid-level, cost or operational impact

**Use when:** Cost efficiency or operational improvement is a strong part of the candidate's evidence and relevant to the role.

> Software engineer specializing in full-stack development using [core stack]. [Implemented or designed] [specific change], reducing [verified cost or operational burden] by [amount and period]. Improved [delivery or operating measure] through [supported capability].

**Select evidence:** Documented cost changes, infrastructure efficiency, deployment effort, or time saved. Do not assume moving to microservices reduces costs; describe the actual intervention and outcome.

### 4. Senior full-stack engineer

**Use when:** The candidate shows sustained technical scope and impact beyond their own tasks; years alone are insufficient.

> Senior Full-Stack Engineer with [relevant experience] delivering [product/domain] using [core stack]. Led [actual technical initiative and scope], achieving [verified outcome under a meaningful constraint]. Improved [team delivery, reliability, onboarding, or architecture outcome] through [specific contribution].

**Select evidence:** Migrations, architecture tradeoffs, coordination, mentoring, and enabling other engineers. Use team size only when known; do not invent management responsibility.

### 5. Python-focused full-stack developer

**Use when:** The posting emphasizes Python, data processing, or analytics-oriented applications and the candidate supports that positioning.

> Full-Stack Developer with [relevant experience] building [application type] using [Python framework and frontend stack]. Delivered [specific system] processing [verified workload] with [measured performance or outcome]. Implemented [relevant asynchronous, database, or integration capability].

**Select evidence:** Actual Python frameworks, data flows, background processing, and database work. Do not insert Django, Celery, Redis, or Lambda unless used.

### 6. JavaScript/TypeScript-focused developer

**Use when:** The target and evidence center on a JavaScript/TypeScript stack.

> Full-Stack Developer building [product type] using [actual JavaScript/TypeScript stack]. Shipped [feature scope] connecting [UI and service capability], achieving [supported outcome]. Applied [relevant testing, API, or delivery capability] to [specific context].

**Select evidence:** UI/API integration, the actual rendering approach, product outcomes, testing, and delivery. Framework names do not automatically establish experience in all their features.

### 7. Backend-to-full-stack transition

**Use when:** The candidate has established backend experience and concrete frontend work supporting a move into full-stack roles.

> Software Engineer extending [verified backend experience and stack] into full-stack development. Built [actual frontend/full-stack project] using [frontend technology], achieving [supported result or scope]. Brings [backend strength] alongside hands-on [new interface capability].

**Select evidence:** Real bridge projects and transferable architecture or data skills. Do not present all backend years as full-stack tenure. For a frontend-to-full-stack transition, invert the established and new layers.

### 8. Full-stack with DevOps emphasis

**Use when:** The job includes deployment/infrastructure and the candidate actually handled those responsibilities.

> Full-Stack Developer with [relevant experience] building and deploying [applications] using [defining stack]. Implemented [pipeline or infrastructure change], improving [verified delivery measure]. Supported [actual operating scope] with [measured reliability or other supported outcome].

**Select evidence:** Release frequency, infrastructure automation, operating scope, uptime with a defined period, and delivery ownership. Using an application hosted on AWS does not establish deploying or operating it.

## Eight bullet transformations

Start with the generic draft, find the missing evidence, then populate the stronger pattern. A rewrite is not permission to invent the additional information in the pattern.

| Generic draft | Evidence to obtain | Stronger drafting pattern |
|---|---|---|
| Responsible for full-stack development | Specific features, candidate contribution, stack, customer/business result | Shipped [features] for [product] using [stack], contributing to [verified outcome]. |
| Worked on frontend and backend | Named workflow, interface/API work, prior process, real time savings | Built [interface] with [frontend] and [API/backend], replacing [process] and saving [verified time]. |
| Improved application performance | Exact measure, baseline, result, intervention, measurement context | Reduced [measure] from [baseline] to [result] by [caching, query optimization, or actual method]. |
| Used React and Node.js for projects | Number/type of applications, rendering architecture, real service workload | Delivered [applications/features] using [actual frontend/rendering approach] and [backend], supporting [verified load or scope]. |
| Participated in code reviews and testing | Personal contribution, testing tools, actual standard changes, outcomes | [Introduced or implemented, as accurate] [review/testing change] using [tools], improving [verified quality measure]. |
| Managed database operations | Schema or migration work, database/ORM, query changes, measured effect | Designed [data structure] in [database] and implemented [migration/query change] using [tool], improving [supported measure]. |
| Deployed applications to the cloud | Actual services, container/cloud/IaC tools, pipeline work, release/uptime evidence | Containerized [services] using [tool] and deployed to [platform] with [automation], reducing [deployment measure] from [baseline] to [result]. |
| Collaborated with teams to deliver features | Actual collaboration or leadership, deliverable, scope, schedule, adoption | [Led, coordinated, or partnered, as supported] with [teams] to deliver [specific feature], achieving [verified schedule or adoption outcome]. |

Use fewer clauses when the evidence supports only part of a pattern. For example, “Implemented Redis caching for the product lookup endpoint” is preferable to a made-up latency reduction. If only the team result is known, use accurate attribution such as “contributed to” rather than claiming sole causation.

## Worked example of truthful tailoring

**Existing evidence:** The candidate built a React reporting page and a Node.js endpoint that reads PostgreSQL data. Operations used it instead of exporting CSVs. No time savings were measured. The candidate has no Kubernetes experience.

**Posting emphasis:** React, Node.js, SQL, workflow automation; Kubernetes preferred.

**Tailored bullet:** Built a React reporting page backed by a Node.js API and PostgreSQL queries, replacing manual CSV exports for the operations team.

**Skills action:** Include React, Node.js, PostgreSQL and SQL if the source supports direct query work. Leave Kubernetes unclaimed and record the preferred-skill gap only in accompanying notes.

**Summary action:** Highlight the workflow improvement without inventing hours saved. Use a different verified metric elsewhere if available; otherwise retain the concrete qualitative outcome.
